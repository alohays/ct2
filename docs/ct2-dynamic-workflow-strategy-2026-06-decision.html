3 The collision it resolves

Ultracode says “orchestrate by default, token cost is not a constraint.” CT2 says “stay lean and serial.” Read carefully they optimize different axes — and that is the whole strategy.

⚡ Ultracode / dynamic workflow — the executor

  • State lives in script variables, not files
  • Resume is session-scoped — a CC exit restarts it fresh
  • Subagents forced into acceptEdits, no mid-run sign-off
  • Budget is a soft hint / fan-out lever, not a stop
  • Optimizes throughput within one session

🛡️ CT2 — the persistent judge

  • Durable .ct2/ file ledger = cold-restart system of record
  • Independent dual review (cc AND cx), no sibling output in prompts
  • Reconciler is the sole automatic path to done/
  • Bounds blast radius by agent count + worktree isolation + scope
  • Optimizes trust across sessions and vendors
✅ They compose. The vendor makes the executor faster/cheaper; CT2 certifies whether the fast output is correct — the one axis a single vendor structurally won’t ship (dual-independent review dilutes its own session). And CT2’s check is structurally deeper than the vendor’s own self-verification: only a different model family (Codex reviewing Claude, and vice-versa) neutralizes self-preferential bias — so Claude’s orchestration lead is a reason to strengthen lens-cx, not retire it. Market signal agrees: “speed isn’t the bottleneck, correctness is” (Faros AI: +91% review time despite +98% more merged PRs).
